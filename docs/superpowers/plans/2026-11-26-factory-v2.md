# Factory v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the prose-driven factory skill with a tested Bun CLI (`factory`) that runs the v2 flow (Discovery → Building → Validation → Deploy), launching every agent as its own `claude`/`pi` process in tmux, with a terminal, tmux and web dashboard UX built around the human.

**Architecture:** A pure state machine (`machine.ts`) decides the next stage from an agent's verdict; a driver (`driver.ts`) executes each stage's side effects (spawn roles in tmux, check output files, commit, push, PR) through injected dependencies, so everything except real tmux/git/gh is unit-tested with fakes. Roles are harness-neutral markdown files; `harness.ts` turns one into a `claude` or `pi` command line. A local Bun server feeds the dashboard and exposes the same commands as the CLI.

**Tech Stack:** Bun (runtime, `bun:test`, `Bun.serve`), TypeScript, tmux, git, gh, Claude Code CLI, pi CLI. No runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-26-factory-v2-design.md`

`<pkg>` below means `stow/factory/.local/share/factory`. Run every `bun` command from `<pkg>` unless a step says otherwise.

## Global Constraints

- Bun only, no runtime dependencies (`@types/bun` as the only devDependency).
- Never run `./stow.sh`, `make switch`, `make boot`, `make mac`, `make update` or `make hardware` (repo rule).
- Nothing repo-specific in `src/` or `roles/`; repo specifics come from the target repo's `AGENTS.md` and `.factory.json`.
- Only the driver pushes or talks to GitHub. Roles never push, never open PRs, never touch `main`.
- Never interpolate user or agent text into a shell command. Prompts go through files; the run script reads them with `"$(cat '<file>')"`.
- `MAX_TRIPS = 3` per cycle, `MAX_DISCOVERY_LOOPS = 3`, one ENV retry per trip.
- Job ID `<YYMMDD>-<slug>`; branch `factory/<job>`; worktree `<repo>/.factory/<job>/`; state `<repo>/.factory/jobs/<job>/`; tmux session `factory-<job>`.
- Default docs paths: `docs/requirements`, `docs/tech-discovery`, `docs/design-docs`, `docs/specs`, `docs/test-plans`.
- Headless claude runs with `--permission-mode auto`. Browser roles run on claude only.
- The dashboard server binds `127.0.0.1` only.
- Commits in this repo: `<type>: <lowercase summary>` (`fea`, `enh`, `fix`, `ref`).
- `stow/pi/.pi/agent/scripts/task-pipeline` is untouched (its 8 known test failures stay 8).

## Output contracts

The driver owns every output path (in `handoff.ts`); roles write to the `Output:` path in their prompt. Role prose (Tasks 17–19) must produce exactly these headings.

| Role                 | Output (relative to)                          | Check                                                                 |
| -------------------- | --------------------------------------------- | --------------------------------------------------------------------- |
| `requirements`       | `<docs.requirements>/<job>.md` (worktree)     | first line `# `; `## Intent`, `## Requirements`, `## Decisions`       |
| `tech-discoverer`    | `<docs.techDiscovery>/<job>.md` (worktree)    | `## Findings`, `## Risks`                                             |
| `designer`           | `<docs.design>/<job>.md` (worktree)           | `## Approach`, `## Alternatives`, `## Questions for the human` (body `None` = no questions) |
| `discovery-reviewer` | `discovery-review-<n>.md` (job dir)           | `VERDICT: PASS`, `VERDICT: REWORK tech-discovery`, `VERDICT: REWORK design` or `VERDICT: ASK` (+ `## Questions`) |
| `planner`            | `<docs.specs>/<job>.md` (worktree)            | `## Acceptance criteria` (numbered), `## Tasks` with `### T<k> …` + `Specialist: <s>`, a `Lenses: a, b` line, `## Run` last (`T1, T2`) |
| `builder-<s>`        | `trip-<t>/build.md` (job dir)                 | first line `STATUS: READY` or `STATUS: BLOCKED`                       |
| `reviewer-<lens>`    | `trip-<t>/review-<lens>.md`                   | `VERDICT: PASS` or `VERDICT: CHANGES`                                 |
| `build-judge`        | `trip-<t>/build-judge.md`                     | `VERDICT: APPROVE`, `CHANGES` or `ESCALATE` (+ `## Questions`)        |
| `test-planner`       | `<docs.testPlans>/<job>.md` (worktree)        | `## Cases`, a `Validators: a, b` line                                 |
| `validator-<kind>`   | `trip-<t>/validation-<kind>.md`               | `VERDICT: PASS` or `VERDICT: FAIL`                                    |
| `validation-judge`   | `trip-<t>/validation-judge.md`                | `VERDICT: PASS`, `FAIL`, `ENV` or `ESCALATE` (+ `## Questions`)       |
| `resolver`           | `trip-<t>/rebase.md`                          | `STATUS: READY` or `STATUS: BLOCKED`                                  |
| `summarizer`         | `pr.md` (job dir)                             | first line `# <PR title>`                                             |

Lenses: `product`, `security`, `code`, `ux`, `ui`. Specialists: `backend`, `frontend`, `mobile`, `data`, `infra`, `general` (unknown → `general`). Validators: `e2e`, `user`, `load`, `capacity` (the test planner may pick only those in config `validators`).

Spec deviation (builder's call): role frontmatter has no `output:` key; the driver is the single owner of output paths.

## Review Focus

1. Feature text or agent output containing quotes, newlines, `$(…)` or backticks must never reach a shell unquoted → pinned in Task 7 (run script) and Task 13 (driver).
2. A driver killed mid-stage and restarted with `factory run` must not re-spawn finished agents, reopen the PR or duplicate commits → Task 13 (resume tests).
3. Two drivers on one job (CLI plus a dashboard button) → the second refuses with a clear message, the dashboard returns 409 → Tasks 13 and 15.
4. The dashboard's file viewer and action endpoints must reject path traversal and cross-origin POSTs → Task 15.
5. v1 jobs in `.factory/jobs/` must show as legacy in `status` and the dashboard and never crash or be driven → Tasks 3, 14, 16.

### Task 4: State machine (pure)

**Files:**
- Create: `<pkg>/src/machine.ts`
- Test: `<pkg>/src/__tests__/machine.test.ts`

**Interfaces:**
- Consumes: `Job`, `Stage`
- Produces:

```ts
export type Outcome =
  | { kind: 'done'; stage: Stage; verdict?: string; reworkStep?: 'tech-discovery' | 'design'; humanQuestions?: boolean; reasonFile?: string; questionsFile?: string }
  | { kind: 'failed'; stage: Stage; reason: string }
export type Command = { kind: 'approve' } | { kind: 'feedback'; file: string } | { kind: 'retry' } | { kind: 'discard' }
export class CommandError extends Error {}
export interface Limits { maxTrips: number; maxDiscoveryLoops: number }
route(job: Job, o: Outcome, limits: Limits, now: Date): Job
applyCommand(job: Job, c: Command, now: Date): Job
isWaiting(job: Job): boolean   // requirements(waitingFor set) | human-review | needs-human | done | discarded
```

Rules (from the spec; every bullet is a test):
- Linear: `requirements → tech-discovery → design → discovery-review`; `planning → build → review → build-judge`; `test-planning → rebase → qa-wait → validation → validation-judge`; `finalize → done`. `planning` done sets `planned = true`.
- `design` with `humanQuestions` → `requirements`, `discoveryLoops + 1`, `waitingFor 'requirements'`, `questionsFile` set.
- `discovery-review`: `PASS → planning` (trip 1, new `TripRecord`); `REWORK` → `reworkStep`; `ASK → requirements` (waitingFor `'requirements'`, `questionsFile`). Each non-PASS is `discoveryLoops + 1`; when it reaches `maxDiscoveryLoops + extraDiscoveryLoops` → `needs-human`, `waitingFor 'failure'`, `capHit 'discovery'`, `resumeStage` = where it would have gone, `reason 'discovery loop cap (3) reached'`.
- `build-judge`: `APPROVE → test-planning`; `CHANGES → planning` with `trip + 1`, `reasonFile`, `envRetries 0`, new `TripRecord`; a trip beyond `maxTrips + extraTrips` → `needs-human`, `capHit 'trips'`, `reason 'trip cap (3) reached'`; `ESCALATE → needs-human`, `waitingFor 'escalation'`, `resumeStage 'test-planning'`, trip unchanged.
- `validation-judge`: `PASS → human-review` (`waitingFor 'human-review'`); `FAIL` like `CHANGES`; `ENV` with `envRetries 0 → qa-wait`, `envRetries 1`; `ENV` with `envRetries 1 → needs-human`, `waitingFor 'escalation'`, `resumeStage 'human-review'`; `ESCALATE → needs-human`, escalation, `resumeStage 'human-review'`.
- `failed` → `needs-human`, `waitingFor 'failure'`, `resumeStage = o.stage`, `reason = o.reason`.
- `approve`: `human-review → finalize`, `ready true`; escalation → `resumeStage`; other `needs-human → finalize`, `ready false`; anything else throws `CommandError('nothing to approve: <id> is in <stage>')`.
- `feedback`: any stage but `discarded`; `cycle + 1`, `trip 1` if `planned` (stage `planning`, new `TripRecord`) else `trip 0` (stage `requirements`, waitingFor `'requirements'`); `reasonFile = file`, `feedbackCount + 1`, `ready null`, waits cleared.
- `retry`: only `needs-human` with `waitingFor 'failure'`; `capHit 'trips' → planning`, `extraTrips + 1`, `trip + 1`; `capHit 'discovery' → resumeStage`, `extraDiscoveryLoops + 1`; otherwise `→ resumeStage`. Else throws `CommandError('nothing to retry: …')`.
- `discard`: any stage but `discarded` → `discarded`; `discarded` throws.
- Every transition sets `waitingSince` to `now` when it enters a waiting state, `null` otherwise.
